## 3. Replenishment: the smallest demo (proposal, pending team agreement)

Build on Alejandro's timeline instead of new machinery:
1. Shared defaults plus per-product `min`, `target` and `auto` or `approval` in the signed rule set (as `reorder_below`,
   `target_units` today, plus one flag).
2. One ordering window (for example 10:00) and a "Run replenishment now" button that runs the same function.
3. For each slot: latest count (camera, sensor or person; old count -> a person), minus nothing for units returned
   within 2 h, plus units already on order (`last_order_qty` of a pending slot); need = target - (count + on order),
   rounded up to the sales unit and lot.
4. One combined quote, fresh at run time; combined total against the auto-limit and the weekly limit; one order or
   one approval; `_recheck` at approval as today; quotes older than 15 min are re-quoted.
5. A returned item never clears an outstanding order (decision C stays strict). The simulator showed the trade-off:
   fewer supplier orders, more stockout hours, partly recovered by urgent exceptions.

Batch expiry cannot be derived: not from general shelf life (none given), not from availability, not from
temperature. Any expiry must come from a person reading the package.

## 5. "Mark quantity unusable" and a temperature warning (assessment)

- **Minimal input:** `POST /stock/{slot}/unusable` with `units`, `status` = `suspected` or `confirmed`, `reason`,
  `person`. `confirmed` writes a count reduction to the timeline (source `person`) and a waste entry; `suspected`
  changes no count and opens a check for a person. Not built.
- **Temperature warning (code today):** the Thermo cold-room alarm sets `cold_room_alarm_c`, and every automatic
  order waits for a person (`rules.check`); the delivery check flags a line that arrived above its `max_temp_c`. A
  warning should create a `suspected` item per affected slot (products with a `maxTemperature` below the reading),
  never a confirmed waste.
- **Limits:** no model (camera or language model) may certify food safety, mark food safe or unsafe, or produce an
  expiry date; only a person confirms waste.
